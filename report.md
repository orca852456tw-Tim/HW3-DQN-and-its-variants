## HW3-1: Naive DQN and Experience Replay

### Basic DQN Theory
Deep Q-Networks (DQN) combine Q-Learning, a classic reinforcement learning algorithm, with deep neural networks. In traditional tabular Q-learning, a Q-table is used to store the expected future rewards for every state-action pair. However, for environments with large or continuous state spaces, maintaining a table becomes computationally intractable. DQN solves this by using a neural network to approximate the Q-value function: `Q(s, a; θ) ≈ Q*(s, a)`. 

The network takes the state as input and outputs the predicted Q-values for all possible actions. The agent selects actions using an epsilon-greedy policy (to balance exploration and exploitation). The network is trained by minimizing the Mean Squared Error (MSE) between its predicted Q-values and the target Q-values computed via the Bellman equation:
`Target = r + γ * max(Q(s', a'; θ))`

### The Role of Experience Replay Buffer
When training a neural network, the optimization algorithms (like SGD or Adam) assume that the training data instances are independently and identically distributed (i.i.d.). However, in reinforcement learning, the sequence of experiences `(state, action, reward, next_state)` generated by the agent is highly correlated temporally. For example, the state at step `t+1` is heavily dependent on the state at step `t`.

If we train the network sequentially on these experiences as they occur, the network will quickly overfit to the most recent trajectory, leading to catastrophic forgetting of past experiences and unstable training. 

The **Experience Replay Buffer** solves this problem by storing a large collection of past experiences in a memory buffer (e.g., a deque). During training, we randomly sample mini-batches of transitions from this buffer. This random sampling:
1. **Breaks Data Correlation**: It shuffles the experiences, breaking the temporal correlation and restoring the i.i.d. assumption, making the optimization process much more stable.
2. **Increases Data Efficiency**: Each experience can be sampled and learned from multiple times, making better use of the collected data.

## HW3-2 Comparison: Enhanced DQN Variants

Based on the training results in `player` mode, we observed improvements in training stability and overall reward collection using Double DQN and Dueling DQN architectures compared to the Naive DQN.

### Double DQN
**The Problem with Basic DQN:** The Naive DQN uses the same neural network to both *select* the best action and *evaluate* the Q-value of that action for the target value calculation (`max(Q)`). Because the max operation is used on noisy Q-value estimates, it consistently overestimates the true Q-values, leading to sub-optimal policies.

**The Solution:** Double DQN decouples action selection from action evaluation. It uses the primary network to select the best action for the next state, and the target network to evaluate the Q-value of that chosen action.
`Target = r + γ * Q_target(s', argmax Q_primary(s', a'))`
This simple change significantly reduces the overestimation bias, leading to more stable learning curves and policies that are less prone to catastrophic drops in performance.

### Dueling DQN
**The Problem with Basic DQN:** In a standard DQN, the network evaluates the Q-value for each state-action pair directly. However, in many states, the choice of action has little to no effect on the expected outcome (e.g., when far away from any danger or reward). A standard DQN still has to learn the Q-value for every action in these states independently.

**The Solution:** Dueling DQN splits the network into two separate streams:
1. **State-Value Stream `V(s)`:** Estimates how good it is to be in a given state, regardless of the action taken.
2. **Advantage Stream `A(s, a)`:** Estimates the relative advantage of taking each action compared to the other actions in that state.

These two streams are then aggregated at the output layer:
`Q(s, a) = V(s) + (A(s, a) - mean(A(s, a)))`
By explicitly separating the state value from the action advantages, the network can learn which states are valuable without having to learn the effect of every action for those states. This is particularly useful in Gridworld environments, where moving in open space often has identical outcomes for several directions. It speeds up convergence and improves robustness.

## HW3-3: Training Tips in Random Mode

Training a DQN in `random` mode is significantly harder because the goal, pit, wall, and player start in random positions every episode. The agent cannot memorize a single path; it must learn to generalize the state representation. To stabilize learning in this highly stochastic environment, two training techniques were incorporated:

### 1. Gradient Clipping (`clip_grad_norm_`)
**Why it's needed:** In deep reinforcement learning, the target values can sometimes spike due to unpredictable large rewards or highly variable Q-value estimates. These large targets cause large gradients during backpropagation, which can lead to catastrophic updates to the network weights, un-doing hours of training.
**Effect:** By clipping the gradient norm to a maximum threshold (e.g., 10.0), we ensure that the network weights are only updated by a reasonable amount in a single step. This prevents the training from diverging and provides much smoother convergence, especially during the early stages of exploration.

### 2. Learning Rate Scheduling (`ReduceLROnPlateau`)
**Why it's needed:** A high learning rate is necessary early in training to explore the parameter space quickly. However, as the network approaches an optimal policy, a high learning rate causes it to oscillate around the minimum instead of converging.
**Effect:** `ReduceLROnPlateau` monitors the training loss (or a validation metric). When the loss stops improving for a specified number of epochs (the "patience"), the scheduler halves the learning rate. This allows the network to fine-tune its weights as it gets closer to the optimal Q-values, improving the final performance and stability of the learned policy.
